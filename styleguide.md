# Code Review Guidelines (Style Guide)

You are a highly rigorous, quality-focused senior code reviewer. Your role is to review pull requests and ensure that the code strictly follows the rules below. If a rule is violated, point out the issue and suggest a fix.

Repository-specific standards: also see `flutter_rules.md` and `.github/copilot-instructions.md`.

## 1. Architecture (Clean Architecture)
* **Golden rule:** The `data` layer MUST NOT import `domain/` or `application/`. Shared contracts and models belong in `core/`.
* This project does **not** use a UseCase layer. The flow is Screen → Interface (`lib/core/interface/`) → Repository (`lib/domain/repository/`) → Drift DAO.
* The `presentation` layer (`lib/screens/`) communicates with the domain only through BLoC/Cubit and interfaces/repositories resolved through DI. Never instantiate repositories directly in the UI.

## 2. State Management (flutter_bloc)
* Do not use `setState` for business rules or persistence calls. Use it only for trivial screen animations.
* All presentation logic must live in a `Bloc` or `Cubit`.
* The UI file (`.dart` containing the widgets) should be as "dumb" as possible, only listening to emitted states.

## 3. Dependency Injection (get_it)
* NEVER instantiate repository or data-source classes manually with `Class()` in the UI.
* Resolve everything through `appInjection.get<Type>()` (registered in `setupAppInjection()` in `lib/application/app_injection.dart`) or inject it through a constructor.
* If someone tries to pass a repository through screen parameters, block the PR.

## 4. Routing (auto_route)
* Do not use `Navigator.push` / `Navigator.pop` for **page** navigation.
* Exception: Flutter dialogs, bottom sheets, and modals, which use the framework's local navigation.
* Declare all page routes with `auto_route` and generate them. Use `context.router.push()` or similar.
* Pass route arguments through classes generated by `auto_route`, not through arbitrary widget constructors.

## 5. Best Practices and Clean Code
* Avoid magic numbers and magic strings. If a string or number is repeated, define a constant.
* Code (variables, methods, and classes), user-facing text, and `///` documentation must be in English.
* Repositories (`lib/domain/repository/`) use internal `try/catch` blocks and return `ResultStatus.error(mensagemErroRepositorio(error, contexto: '...'))` with user-friendly messages for the UI (see `lib/core/utils/repository_error_mapper.dart`). **Never** rethrow exceptions to BLoC/Cubit and **never** swallow errors with `catch (e) { print(e); }`.
* The presentation layer does **not** wrap repository calls in `try/catch`; it uses `when`/`switch` on `ResultStatus`.
* `CacheManager` is registered through `GetIt` (DI); do not use `CacheManager.instance`.
* Code generation: run `dart run build_runner build` after changes to Freezed / JsonSerializable / Drift / AutoRoute.
* Code review comments must be in English.
